# EasyGet 手动打包说明

这份文档只说明本地构建和打包验证。正式 GitHub 版本的唯一发布入口是 `scripts/release.ps1`，不能把手动打包、普通 `main` 推送和正式发布混为一谈。

## 0. 正式发布入口

先把目标版本的 `CHANGELOG.md` 条目和待发布内容作为普通提交推送到 `main`。不要手工修改 `EasyGet.csproj` 的版本；发布脚本会在确认阶段统一修改。确认 `main` 工作区干净且与 `origin/main` 同步后执行：

```powershell
# 默认只读预检（也可显式添加 -DryRun）
./scripts/release.ps1 -Version 1.4.3

# 展示预检结果并获得用户明确确认后发布
./scripts/release.ps1 -Version 1.4.3 -Publish
```

`-Publish` 会更新项目版本、创建 release commit 与 annotated tag，并将 `main` 和 tag 一起推送。正式发布禁止直接使用 `git tag`、`git push origin vX.Y.Z` 或 `gh release` 命令。已经推送的 `v*` tag 永远不能删除、移动或复用；发布后需要修复时必须递增 SemVer，例如从 `v1.4.2` 升到 `v1.4.3`。

GitHub 仓库已启用 `Immutable releases`，下一版本开始服务器会锁定公开 Release 的 tag 与资产；任何 Agent 都不得关闭该保护。

完整的发布前置条件、工作流等待与更新冒烟检查见 [`docs/release_and_updater_manual.md`](../docs/release_and_updater_manual.md)。

当前项目是 `WPF + .NET 8`，本地打包使用 `dotnet publish` 生成 `win-x64` 自包含发布目录。

## 1. 打包前准备

确认本机具备以下条件：

- Windows 系统
- 已安装 `.NET 8 SDK`
- 在项目根目录打开终端：
  `E:\AIMadeupTools\01_DesktopApps\EasyGet`

可先执行下面命令确认 SDK 是否正常：

```powershell
dotnet --version
```

## 2. 推荐的本地打包脚本

在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\publish-win-x64.ps1
```

脚本会依次执行：

- `dotnet restore`
- `dotnet test`
- `dotnet publish`
- 检查发布目录中的 `EasyGet.exe`
- 生成 zip 包

只想做发布 smoke 检查、不生成 zip 时，可以执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\publish-win-x64.ps1 -SkipZip
```

常用参数：

- `-Configuration Release`：使用正式发布配置
- `-Runtime win-x64`：面向 64 位 Windows
- `-SkipTests`：跳过测试，仅用于已经单独跑过测试的场景
- `-SkipZip`：只生成发布目录，不压缩 zip
- `-Version X.Y.Z`：可选的版本校验值，必须与 `EasyGet.csproj` 中的 `<Version>` 一致；省略时自动读取项目版本

需要在本地验证安装包时，先安装 Inno Setup 6，然后执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-installer.ps1
```

该脚本会同时生成 `EasyGet-Setup-vX.Y.Z.exe`、`EasyGet-win-x64-Release.zip` 和 `easyget-update.json`。这些只是本地产物，不会创建正式 GitHub Release。

## 3. 手动打包命令

在项目根目录执行：

```powershell
dotnet publish .\EasyGet.csproj -c Release -r win-x64 --self-contained true
```

说明：

- `-c Release`：使用正式发布配置
- `-r win-x64`：面向 64 位 Windows
- `--self-contained true`：把 .NET 运行时一起打进去，目标机器不用额外安装 .NET

## 4. 打包产物位置

脚本默认输出目录在：

```text
artifacts\publish\Release\win-x64\
```

手动 `dotnet publish` 的默认产物目录在：


```text
E:\AIMadeupTools\01_DesktopApps\EasyGet\bin\Release\net8.0-windows\win-x64\publish\
```

其中最重要的是：

- `EasyGet.exe`
- 以及同目录下的全部 `dll`、运行时文件、多语言资源目录

## 5. 发给别人时怎么处理

不要只发 `EasyGet.exe`，要把整个 `publish` 文件夹一起打包。

推荐做法：

1. 打包完成后，进入 `publish` 目录。
2. 选中里面全部文件和文件夹。
3. 压缩成一个 zip 包。
4. 把 zip 包发给别人。

对方使用时：

1. 解压整个 zip。
2. 直接双击 `EasyGet.exe` 运行。

## 6. 首次运行的注意事项

程序首次运行时会自动检查并下载以下工具：

- `yt-dlp`
- `ffmpeg`

它们不会放在 `publish` 目录里，而是默认下载到：

```text
%LocalAppData%\EasyGet\tools
```

也就是通常类似：

```text
C:\Users\你的用户名\AppData\Local\EasyGet\tools
```

这意味着：

- 如果目标电脑可以联网，首次启动后程序会自动补齐这些工具。
- 如果目标电脑不能联网，需要先在一台能联网的机器上运行一次程序，然后把 `%LocalAppData%\EasyGet\tools` 整个目录一起拷过去。

## 7. 配置和历史记录位置

程序运行后还会在本地生成这些数据：

- 配置文件：`%LocalAppData%\EasyGet\config.json`
- 下载历史：`%LocalAppData%\EasyGet\history.db`
- 崩溃日志：`publish\logs\`

如果只是发安装包给别人，一般不需要带上这些文件。

## 8. 每次本地打包建议这样做

建议固定按下面顺序执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\publish-win-x64.ps1
```

打完后检查：

- `publish` 目录是否生成
- `EasyGet.exe` 是否存在
- 本机是否能正常双击启动

## 9. 当前项目已验证的命令

这个项目已经实际验证过下面这条命令可以正常出包：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\publish-win-x64.ps1 -SkipZip
```

输出目录为：

```text
artifacts\publish\Release\win-x64\
```

## 10. 常用备注

- 如果只是“给 Windows 64 位用户直接用”，继续用 `win-x64` 就行。
- 正式分发优先使用 `EasyGet-Setup-vX.Y.Z.exe` 安装包；便携分发使用 `EasyGet-win-x64-Release.zip`。
- 普通代码推送只更新 `main`；只有经过 `release.ps1` 两阶段流程的操作才是正式发布。
- 正式发布必须等待 `Build and Release` workflow 成功，并验证四个 Release 资产和 latest manifest 后才能宣布完成。
