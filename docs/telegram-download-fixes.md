# Telegram 私有频道／群组下载排查与修复

## 排查结论

参考本机 `F:\AI\AIMadeupTools\07_AITools\TGMessage\tg_extractor.py`，并核对项目锁定的 WTelegramClient 4.4.6 实现。TGMessage 使用 Telethon 的会话、实体解析、代理和媒体下载接口，没有独立的分块或断点续传算法，不能直接移植 Python 的 `cryptg` 加速或把随机休眠当作可靠的限流机制。

| 原有问题 | 影响 | 修复 |
| --- | --- | --- |
| 私有会话只调用一次 `Messages_GetDialogs` | 较早或归档的频道／超级群被错误提示为未加入 | 按会话游标翻页，分别查询主列表与归档，保留完整的频道访问参数；忽略侧载的 `min` 频道记录 |
| 只支持 `/c/频道/消息` | `/c/频道/话题/消息` 不能识别 | 统一解析公开／私有话题链接、`telegram.me`、预览链接和 `tg://privatepost`；剪贴板与下载路由使用相同规则 |
| 下载仅检查内存中的 `User` | 重启后依赖设置页先完成会话恢复 | 下载入口恢复已有登录会话；没有已授权会话时提示登录，不发送验证码；查询登录状态不重复提交手机号 |
| 代理握手假定一次收齐响应 | 分包导致失败、残留握手数据或丢失隧道首包 | 完整异步读写 SOCKS5／HTTP CONNECT，按状态码判断，支持认证、IPv6 和连接超时 |
| 直接写正式媒体文件 | 中断留下不完整文件或覆盖旧文件 | 在同目录写独立临时文件，校验大小后原子替换；失败／取消清理本次临时文件 |
| 取消依赖下一次下载进度回调 | 网络卡住时无法取消，阻塞后续任务 | 无数据超过 120 秒超时；取消或超时时中止连接，封闭输出流并回收传输；下次下载重新恢复已有会话 |
| 范围下载只要一条成功就算完成 | 文件缺失却显示完成 | 缺失／服务消息单独跳过，实际下载失败则任务失败并列出消息 ID，保留已成功文件 |
| 文档默认名不带扩展名、非文件媒体也创建文件 | 视频无扩展名、出现空媒体文件 | 按 MIME 类型补扩展名，原图尺寸由库选择，非文件媒体只保存可用文本 |

文件引用过期时重新获取消息后重试；短期 `FLOOD_WAIT` 按服务器指定时间等待，支持取消并限制重试次数；长时间限流明确提示稍后重试。

## 验证

离线回归使用伪 Telegram 客户端和本机 TCP 代理服务器，不读取真实私聊或登录凭据。覆盖跨页／归档查找、访问参数、会话恢复、话题链接、代理拆包与认证、短文件／中断／取消、闲置超时和传输回收、范围部分失败、过期引用及整数边界。

```powershell
dotnet test EasyGet.Tests/EasyGet.Tests.csproj -c Release
```

真实账号验收：重启 EasyGet 后直接粘贴已加入的私有频道消息链接；再验证归档群组和带话题编号的具体媒体消息；检查媒体能打开、大小符合预期，断网或取消后不会把临时文件当成完成文件。离线测试不能验证特定账号的成员权限、真实 Telegram 网络或服务端限流情况。

## 当前范围

- 私有内容要求 EasyGet 绑定的账号本身有访问权限。不会自动加群，也不会更改 Telegram 权限。
- 话题入口本身可能是服务消息，需复制话题内的具体消息链接。
- `?comment=` 指向另一讨论组，当前给出明确提示，需复制讨论组内的具体消息链接。
- 单条链接下载该条消息的文件／照片与文本；不自动扩展整组相册。
- 重试从当前文件开头下载；不宣称字节级断点续传。

官方依据：[Telegram 消息链接](https://core.telegram.org/api/links#message-links)、[min 对象与访问参数](https://core.telegram.org/api/min)、[WTelegramClient 4.4.6](https://github.com/wiz0u/WTelegramClient/tree/4.4.6/src)。
