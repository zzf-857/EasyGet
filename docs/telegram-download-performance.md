# 免费 Telegram 账号的下载提速

## 能改善什么

Telegram 官方说明，Premium 会解除账号在 Telegram 一侧的媒体下载速度限制，但网络、代理和设备仍会影响速度。因此，免费账号的客户端优化目标是减少空等、重复传输和磁盘开销，不承诺突破服务端上限，也不承诺固定倍速。

WTelegramClient 4.4.6 默认每块 512 KiB、两个块并发。EasyGet 对大小与数据中心已知的视频／文档采用以下策略：

- 每块仍为 512 KiB，最多四块预取。所有偏移和请求大小符合 Telegram 对齐规则，包括最后一块。
- 复用同一账号的媒体数据中心连接，不按块创建连接或重复登录；队列同时处理一个 Telegram 文件。
- 分块可以并行返回，按文件顺序写入，预取缓存最多四块，避免每个乱序分块都触发磁盘 seek／flush。
- 收到 `FLOOD_WAIT_X` 或 `FLOOD_PREMIUM_WAIT_X` 时，保留已成功的分块，只重试被限流的分块；等待完整的服务器指定时间。所有待发媒体请求共享冷却时间，后续并发降为一块。
- 已知冷却时间跨后续视频、取消和客户端重建保留在当前 EasyGet 服务中。不会通过重新连接或换文件提前发出下载请求。
- 单次等待超过十分钟，或同一块用尽三次限流重试时，停止并显示原因。冷却期间的本地进度心跳不发送任何额外 Telegram 请求，下载速度显示为零，用户仍可取消。

已知大小的文档使用新的分块路径；照片及缺少必要元数据的媒体保留 WTelegram 的兼容路径。文件引用过期仍由消息层刷新后重试；本次没有新增跨任务、跨进程的断点续传。

## 如何判断实际收益

使用同一个较大的视频、同一代理节点、相近时间，比较完整下载耗时与平均速度。不要同时在官方客户端、浏览器或其他程序下载同一账号的文件，以免带宽与限流互相影响。

如果原来受网络往返时间或文件重下影响，分块并发与局部重试可以减少等待。如果本来已经达到 Telegram 的账号限速或代理带宽上限，增加并发可能没有收益，遇到限流时反而应降低并发。更换代理只能改善不佳的网络路径，不能保证提升账号的服务端限速。

日志会显示分块策略、服务器等待和降并发信息，方便区分网络慢与服务器主动限制。离线延迟模拟和回归测试只能证明并发、请求数量、重试范围与数据正确性，不能替代真实账号测速。
